# 旧Macブランチの扱い

調査日: 2026-10-23。

Ubuntu 24.04向けの刷新では、`mac_mojave10.14`を保守対象から外してよい。Mac固有の導入処理は新構成に必要なく、現状のインストーラーも存在しないAtom用スクリプトを参照している。ただし、このブランチには認証トークンらしい値が残っているため、認証情報の失効を先に確認する。今回、リモートブランチの削除や履歴の書き換えは実施していない。

## Ubuntu用の履歴とは別に分岐している

調査時のMac側の先端は`7b3b004e`、`origin/master`の先端は`7f0229f0`である。両者の共通祖先は`5e563dfd`で、Mac側にはmasterから到達できないコミットが50件ある。初期の変更には別ハッシュで重複したものもあるが、Git上で「すべてマージ済み」のブランチではない。

Ubuntu用の`master → ubuntu1804 → ubuntu2004`の履歴は、Macブランチの参照を消しても残る。Mac固有の先端ファイルは全10件を調査済みで、内容は[全ブランチの調査記録](ubuntu-24.04-audit.md)にまとめた。将来Mac設定を再利用する予定がなければ、Ubuntu刷新のためにMac側の履歴をマージする必要はない。

## ブランチの削除だけでは認証情報を除去できない

`atom-settings`のtoken項目は、有効性を確認していない。値はこの文書にも新しい設定にも転載しない。確認できた到達関係は次のとおりである。

| 追加コミット | その履歴に到達できる調査時のブランチ | 先端での状態 |
|---|---|---|
| `d29dd60b` | `origin/mac_mojave10.14` | `atom-settings`が残る |
| `c04f9db9` | `origin/master`、`origin/ubuntu1804`、`origin/ubuntu2004` | `0173cc36`でファイルを削除済み。過去の内容は残る |

したがって、Macブランチだけ削除しても、Linux側の過去履歴から認証情報を取り出せる状態は変わらない。GitHubも、漏えいした認証情報では最初に失効・再発行を行い、履歴削除の要否を別に判断する手順を案内している。履歴を書き換えても、別のclone、fork、PR参照などへの対応が残る場合がある。[GitHub公式の削除手順](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

次に行う順序は次のとおりである。

1. `atom-settings`で使っていた認証情報をアカウント設定で確認し、利用可能なものは失効・再発行する。
2. Mac固有の履歴を今後使わないことを確認した上で、リモートの`mac_mojave10.14`参照を削除する。削除は別途明示的に実施する。
3. 過去履歴からも内容を消す必要があれば、Linux側を含む全参照と他のcloneへの影響を調べ、履歴整理を別作業として計画する。保存用タグの追加だけでは情報の除去にならない。

到達関係は`git merge-base`、`git rev-list --left-right --count`、`git branch -r --contains`、`git log --all -- atom-settings`で確認した。認証情報を使ったAPI呼び出しやログインによる有効性確認はしていない。
