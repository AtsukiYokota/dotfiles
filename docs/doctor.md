# インストール状態の診断

新しい端末で次を実行します。

```bash
doctor
```

正常終了したインストールのモジュール記録を基に、コマンド、設定ファイル、LSPの実行ファイル、ROSのセットアップ、Markdown描画用ファイルのハッシュ、フォント、クリップボード、GUIセッションの状態を確認します。
診断ではネットワーク接続、sudo、インストール、設定変更を行いません。
シェルの起動設定やプロジェクトのコードも実行しません。

| 表示 | 意味 |
|---|---|
| `PASS` | 表示された確認項目を満たしています |
| `WARN` | 版の相違、PATHやセッションの不足など、確認が必要です |
| `FAIL` | 選択したモジュールの必須ファイル・コマンドが欠けている、または整合性を確認できません |
| `SKIP` | 実行による副作用を避けるため、手動確認が必要です |

修復が必要な場合は、各項目の下に対応する操作を表示します。
終了コードは`FAIL`があれば`1`、`WARN`と`SKIP`だけなら`0`です。
不正な引数は`2`になります。

古いインストールで成功記録がない場合は、見つかったコマンドから対象を推定し、不足項目を警告として表示します。
調べる対象を明示することもできます。依存モジュールも確認対象になります。

```bash
doctor --modules shell,neovim,ros2
doctor --json
```

まだ`doctor`がPATHにない場合は、リポジトリから実行できます。

```bash
python3 commands/doctor.py --modules shell,neovim,ros2
bash setup_all.sh --doctor
```

JSON出力にはホスト名、ユーザー名、メールアドレス、ホームディレクトリの実パス、環境変数の値を含めません。
クリップボードの中身も読み取りません。

`PASS`は実際の編集・通信・画面表示まで保証するものではありません。
たとえばLSPは実行ファイルの存在、GUIは表示用の環境変数、クリップボードは利用可能なコマンドを確認します。
ROSのノードやGUIを起動せず、tmuxサーバーにも接続しません。
補完はNeovimの`:DotfilesLsp`、ROSの通信やプレビューは[動作確認手順](verification.md)で確認してください。

脆弱性の確認は別の範囲です。
Node.js・Brotliについての調査時点を明記した確認には、`python3 scripts/check-security.py`を使用してください。
